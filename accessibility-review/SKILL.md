# Accessibility review

## Inputs
Target URL or authorized local build, intended audiences, supported devices.

## Procedure
1. Inspect semantic landmarks, heading order, alternative text, forms, labels and error messages.
2. Test keyboard navigation, focus appearance and logical order, escape/close behavior and skip navigation.
3. Use axe-core or an equivalent approved auditor only in an authorized environment.
4. Independently verify findings; automated checks alone cannot prove WCAG conformance.
5. Report defect, reproduction, impact, severity, suggested fix and evidence.

## Output
A prioritized accessibility report, a list of unknowns, and recommended manual follow-up. Never claim compliance without the necessary testing.
